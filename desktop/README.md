# MatroOS Desktop — тестовая Linux-редакция

MatroOS Desktop строится на **Debian 13, ядре Linux и KDE Plasma**. Мы
настраиваем оболочку и набор своих приложений, а необходимые сторонние системные
компоненты, драйверы, библиотеки и темы остаются. Отдельное экспериментальное
собственное ядро YoroOS в этот ISO не входит.

## Пробный образ

* UEFI Live для тестирования в виртуальной машине Hyper-V поколения 2;
  установщика на диск и постоянного сохранения данных пока нет.
* Ядро Debian, Live Boot, X11, Plasma и SDDM, сеть и звук; модули
  Hyper-V storage, network, mouse и keyboard перечислены для initramfs.
* Live-пользователь `yoro`, вход в Plasma X11 настроен автоматически.
  Резервный пароль для ручного входа — `live`. Не используйте этот открытый
  тестовый режим для личных данных.
* Yoro-приложения: файлы, блокнот, настройки, медиа, консоль, компьютер,
  корзина, калькулятор, Paint; Matronix Browser из репозитория владельца.
  Поддержка запуска приложений Windows в этой сборке не заявляется.
* Графический запуск и оборудование Hyper-V проверяются пользователем в ВМ.
  Успешная сборка и проверка в QEMU не подтверждают работу Hyper-V.
* Свои значки приложений и обои. CI-образ включает выбранные иконки Colloid и
  курсор Bibata Modern Ice (GPL-3.0); при локальной сборке без переменной
  `YORO_THEME_INPUT_DIR` используются стандартные иконки и курсор.
* Необязательные nano, htop, git, curl не запрашиваются явно. Системные
  приложения, попавшие как зависимости, скрываются в меню через XDG-override,
  а не удаляются; их наличие и видимость в других местах не исключены.

## Hyper-V

Создайте ВМ поколения 2: 4 ГБ RAM (8 ГБ комфортнее для браузера), 2 виртуальных
ядра, ISO первым в порядке загрузки. Secure Boot лучше выключить для первого
теста: корректность подписанной загрузки именно этого образа не подтверждена.
При тестировании Live-образу виртуальный жёсткий диск не нужен. Всё сделанное
в Live-сессии пропадает после выключения.

## Сборка

```sh
sudo apt install live-build xorriso squashfs-tools grub-pc-bin grub-efi-amd64-bin
sudo ./distro/build-iso.sh out
python3 -m unittest discover -s tests -p 'test_desktop_branding.py'
python3 -m unittest discover -s tests -p 'test_build_staging.py'
```

Для полного оформления используются исходники тем в `YORO_THEME_INPUT_DIR`;
их подготовку демонстрирует workflow `Build YoroOS Desktop ISO (Linux)` на GitHub. `out/` содержит ISO
и его SHA-256. При первой загрузке проверяйте видимый рабочий стол, мышь,
клавиатуру, панель и запуск Matronix Browser; при проблеме пришлите скриншот.

CI отдельно проверяет UEFI-загрузку в QEMU и запуск процесса Plasma после
автовхода. Для теста сессии QEMU запускается с временным отладочным shell на
виртуальном последовательном порту; этот параметр **не входит в ISO**. Такие
проверки не подтверждают работу графики или устройств ввода Hyper-V.

### Исполняемые файлы и стекло

В приложении «Файлы» локальные ELF, AppImage, скрипты с shebang и `.sh`, а
также исполняемые файлы Windows определяются до передачи в KIO. При запуске
показывается предупреждение с кнопкой «Выполнить в любом случае». На странице
«Система» в настройках можно отключить подтверждение **только для Файлов**.
Это опасно: программы запускаются с правами пользователя и могут изменять его
файлы. Для ELF и скриптов с shebang при необходимости добавляется право запуска
для владельца. Запуск может быть запрещён файловой системой, правами или
политиками ОС. Windows `.exe` требует отдельно установленного Wine; он не
включён в образ и совместимость не гарантируется. Диалоги KIO в других
приложениях эта настройка не изменяет.

Приложения MatroOS используют непрозрачное оформление. Эффект Liquid Glass и
размытие KWin в этой сборке отключены. Сторонние приложения могут сохранять
собственные элементы интерфейса.

### Minecraft Java и Matronix Launcher

Образ включает оригинальный MatronixPrismLauncher Linux v0.1.0-alpha.14 из
[релиза проекта](https://github.com/MatronixOwner/MatronixLauncher/releases/tag/v0.1.0-alpha.14)
и OpenJDK 21/25. Сам Minecraft в образ не входит: для загрузки и игры нужны
интернет, подходящий аккаунт и разрешение/право на использование игры.
Совместимая Java зависит от версии Minecraft; старым версиям может потребоваться
другая версия Java. Live-сессия не сохраняет аккаунт, установленные игры и миры.

В Hyper-V Gen2 аппаратное 3D-ускорение может отсутствовать: Mesa тогда
использует программный рендерер llvmpipe, игра может идти очень медленно или
не запуститься. Кнопка запуска лаунчера не гарантирует работоспособность игры.
Графические возможности можно проверить командой `glxinfo -B` в терминале.

Сборка образа требует `YORO_THEME_INPUT_DIR` с Kora, Bibata и проверенным по
SHA-256 официальным `matronix-launcher.tar.gz`; workflow автоматически
скачивает фиксированные версии и сопровождающие лицензии. Установщик отдельно
не включён; это Live-образ.
