# YoroOS: нативное направление

Цель — собственные ядро и файловая система, работающие без Linux. Текущая
версия **0.3.0-dev1** — ранний консольный прототип, а не готовая настольная ОС.

## Что работает сейчас

* BIOS: загрузчик и 32-битное ядро YoroOS, текстовый интерфейс и PS/2.
* UEFI/Hyper-V Gen2: отдельная UEFI-программа с консолью прошивки. Она не
  загружает BIOS-ядро и не вызывает ExitBootServices, то есть это пока не
  самостоятельное ядро на Gen2. Linux для работы ей не нужен.
* Общий прототип YoroFS в памяти: один плоский каталог, до 16 файлов, имена
  до 31 ASCII-символа (`A-Z`, `a-z`, `0-9`, `.`, `_`, `-`), до 511 байт на
  файл. Shell ограничивает длину всей команды 127 символами.
* Команды `ls`, `write <имя> <текст>`, `cat <имя>`, `rm <имя>`, `fsinfo`.
  `write` перезаписывает существующий файл; пустой текст создаёт пустой файл.

**Всё в RAM: файлы удаляются при перезагрузке или выключении.** Постоянной
дисковой файловой системы, установщика, GUI, сетевого стека и поддержки
Windows-приложений здесь нет. Текущие Python/Qt приложения, включая Matronix
Browser, не запускаются на этом ядре: понадобятся среда исполнения, графика,
сеть и перенос зависимостей. Старый релиз Desktop использует Linux и не
представляет нативную YoroOS.

## Проверка

Сборка `make`, проверка файловой подсистемы `make test`, структура ISO `make
verify`. BIOS-цепочка тестируется `python3 tools/emutest.py build/yoroos.iso`
(пакет Python `unicorn`). Эти тесты не подтверждают работу UEFI/Hyper-V.

В Hyper-V создать виртуальную машину поколения 2, выключить Secure Boot (наш
EFI-загрузчик не подписан), подключить ISO к DVD, поставить DVD первым в
порядке загрузки. Затем в появившейся консоли ввести:

```
fsinfo
write test.txt hello YoroOS
ls
cat test.txt
rm test.txt
cat test.txt
```

Последняя команда должна сообщить `File not found.` Перезагрузка также
очищает все файлы. Здесь нет записи на виртуальный диск. UEFI-путь этого
образа пока не проверялся на Hyper-V; нужен отчёт тестера.

## Следующие этапы

1. Загрузчик UEFI x86-64 → настоящее 64-битное ядро, карта памяти,
   ExitBootServices, обработчики исключений и вывод через framebuffer;
   затем поддержка ввода и устройств Hyper-V без зависимости от boot services.
2. Управление памятью, прерывания, таймер и планирование; тесты запуска ядра
   в UEFI/Hyper-V.
3. Драйверы виртуальных блочных устройств Hyper-V и безопасная работа с
   отдельным тестовым виртуальным диском. Никакого форматирования без явного
   выбора пользователем.
4. Спецификация и реализация **дискового** YoroFS: размещение метаданных,
   файлов и каталогов, проверка повреждений, долговечная запись и тесты
   сохранения после перезапуска. RAM-прототип не является этим форматом.
5. Графическая оболочка, ввод, сеть и прикладная среда; затем перенос своих
   приложений и оценка возможности запуска Matronix Browser и Windows-софта.

## Экспериментальный графический экран UEFI (0.3.0-graphics-dev1)

`make graphics-iso` создаёт отдельный `build/yoroos-native-graphical.iso`.
В UEFI загрузчик получает framebuffer и карту памяти, вызывает
ExitBootServices и передаёт управление 64-битному коду ядра в том же EFI-образе.
Ядро переключается на собственный стек, отключает прерывания и рисует статичный
экран напрямую в framebuffer. Linux и графические библиотеки не используются.
Текущая реализация сохраняет таблицы страниц прошивки, собственной настройки
памяти или обработчиков прерываний пока нет.

Это **не интерактивный рабочий стол**: нет мыши, клавиатуры, окон, приложений,
сети или записи на диск. Иконки временные; выбранный владельцем Colloid ещё не
включён (нужна проверка лицензии). BIOS-загрузка этого образа по-прежнему
запускает старую текстовую 32-битную версию. Для Hyper-V Gen2 нужен выключенный
Secure Boot, поскольку EFI-образ не подписан. Проверять только в виртуальной
машине; UEFI/Hyper-V ещё не подтверждён реальным запуском.

Тесты рендеринга: `make test-graphics`; автоматическая загрузка с UEFI QEMU/OVMF
проверяется GitHub Actions через последовательный маркер после рисования.
